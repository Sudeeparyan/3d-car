# White Mustang birthday model

A **160 mm long display model** of the friend's 2018+ Mustang GT, matched to the six photographs: white body, gloss-black running-pony grille badge, slim smoked headlamps with LED slashes and amber markers, black glass, mirrors and lip spoiler, the four-hash-mark rocker stripe, black "5.0" fender badges (readable on both sides), seven-Y-spoke gunmetal RTR Aero 7 wheels with the RTR centre-cap monogram and red calipers, tri-bar tail lights, quad exhaust tips and a rear number plate (blank until the registration is supplied — `python run.py plate <TEXT>`). The finished gift has one body and four glued, fixed wheels.

**Open [START HERE](START_HERE.html)** for the finished model and file links. See the [colour and assembly diagram](previews/00_COLOR_AND_ASSEMBLY_DIAGRAM.png) and the [print and finishing guide](docs/PRINT_AND_PAINT_GUIDE.html) before taking the files to college. A [plain-text guide](docs/PRINT_AND_PAINT_GUIDE.md) is also available.

Everything in this folder is **generated by scripts** from the openly licensed source body and the photographs; no Blender or slicer is needed. `run.py` is the single entry point.

---

## 1. Quick start

```bash
python run.py setup     # once: creates .venv, installs requirements.txt, npm install
python run.py check     # confirms Python, packages, Node, Chrome and the input files
python run.py view      # opens the interactive 3D viewer in your browser
python run.py build     # regenerates every print file, preview and the hand-off ZIP
```

`python` means any Python 3 on your PATH (`python3` on macOS/Linux, `py -3.12` or `python` on Windows). `run.py` itself only uses the standard library; it runs every pipeline step with the project's own `.venv` interpreter.

If you only want to **look at or print the model**, nothing needs to be installed: the finished files are already in `print/`, `multicolor/` and `Mustang_Gift_Package.zip` (see section 5).

## 2. Install (transferring to another computer)

### What to copy

Copy the **whole project folder** (or `git clone` it). Everything needed to rebuild is tracked, including `reference_assets/` (source body) and `images/` (the six photographs). These folders are *not* copied and are recreated on the new machine:

| Folder | Why it is missing | How it comes back |
|---|---|---|
| `.venv/` | machine-specific Python environment | `python run.py setup` |
| `node_modules/` | machine-specific Node packages | `python run.py setup` |
| `work/` | cached intermediate meshes (several minutes to rebuild) | first `python run.py build` |
| `validation/likeness/iter_*/` | old scored iterations, not needed | — |

### Requirements

| Tool | Needed for | Install |
|---|---|---|
| **Python 3.12** (3.11 minimum) | all geometry, colour, validation and packaging steps | <https://www.python.org/downloads/> — on Windows tick *Add python.exe to PATH* |
| **Node.js 18+** | renders: previews, likeness score, contact sheet | <https://nodejs.org> (LTS) |
| **Google Chrome** (or Chromium / Edge) | the renderer drives it headless | <https://www.google.com/chrome/> |

Node and Chrome are only needed for the render steps. Without them `python run.py build` still produces every print file and the ZIP, reusing the existing `previews/` and likeness report.

### Step by step

```bash
cd path/to/3d-car
python3.12 run.py setup        # Windows:  py -3.12 run.py setup
python run.py check            # every line should say [ok]
```

`setup` does three things: creates `.venv/` and installs the pinned Python packages from [requirements.txt](requirements.txt) (numpy, scipy, trimesh, manifold3d, scikit-image, OpenCV, Pillow), runs `npm install` for three.js and puppeteer-core, and looks for Chrome. It is safe to run again.

Manual equivalent, if you prefer:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt      # Windows: .venv\Scripts\pip install -r requirements.txt
npm install
```

### Troubleshooting

- **`Python 3.11+ is required to create the environment`** — the `python` that launched `run.py` is too old. Run `python3.12 run.py setup` (macOS/Linux) or `py -3.12 run.py setup` (Windows).
- **`No Chrome/Chromium/Edge found`** — install Chrome, or point at the browser you have: `CHROME_PATH="C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe" python run.py build`. Or skip renders: `python run.py build --no-render`.
- **`pip install` fails to find a wheel** — you are probably on Python 3.9/3.10 or a 32-bit interpreter. Delete `.venv/` and redo `setup` with 3.12 (64-bit).
- **Port 8000 already in use** for `view` — `python run.py view --port 8001`.
- **Windows PowerShell blocks `.venv\Scripts\activate`** — you never need to activate; `run.py` calls the venv interpreter directly.

## 3. Run it

| Command | What it does |
|---|---|
| `python run.py setup` | Create `.venv`, install `requirements.txt`, `npm install`, check for Chrome. |
| `python run.py check` | List what is installed/missing and whether the generated files exist. Exit code 0 when everything is present. |
| `python run.py view` | Serve the folder on <http://127.0.0.1:8000> and open `viewer.html` (interactive 3D: painted assembly, colour parts, print STLs). `--start` opens `START_HERE.html` instead. Ctrl+C stops it. |
| `python run.py build` | Full pipeline (section 4). First run ≈ 5–12 min for the body (machine dependent) plus ≈ 2 min for the rest. |
| `python run.py build --skip-body` | Same, reusing the cached `work/body_clean.stl`. Use after changing anything in `scripts/geometry.py` or `scripts/regions.py`. |
| `python run.py build --no-render` | Skip the Node/Chrome steps (renders, likeness score, previews). |
| `python run.py build --name iter_16` | Keep this run's renders and score under `validation/likeness/iter_16/` instead of `current/`. |
| `python run.py step --list` | Show the individual pipeline steps. |
| `python run.py step multicolor validate package` | Run only the named steps, in that order. |
| `python run.py plate KA01AB1234` | Write the registration into `PLATE_TEXT` in `scripts/geometry.py`. Then run `build --skip-body`. |
| `python run.py clean` | Delete `work/` so the next build starts again from the source body. |

The older shell wrappers `scripts/iterate.sh` and `scripts/promote_likeness.sh` still work on macOS/Linux and do the same as `run.py build`'s render/likeness/promote steps.

## 4. End-to-end: how the files are produced

`python run.py build` runs these steps in order. Each is a script in `scripts/` and can be run alone with `python run.py step <name>`.

| # | Step | Script | Input → output |
|---|---|---|---|
| 1 | `build_body` | `build_body.py` | `reference_assets/.../mustangBodyOnly.stl` → scaled to 160 mm, voxel-repaired, smoothed, decimated → `work/body_clean.stl` (cached; 5–12 min) |
| 2 | `build_parts` | `build_parts.py` + `geometry.py` | adds grille, lamps, mirrors, spoiler, badges, plate, wheel pads; generates the RTR wheel → `print/01…06*.stl`, `work/manifest.json` |
| 3 | `paint` | `paint_mesh.py` + `regions.py` | assigns a colour region to every triangle → `work/*_painted.npz` |
| 4 | `assemble` | `assemble_obj.py` | body + four wheels at their final positions with materials → `model/Mustang_160mm_assembled.obj/.mtl` |
| 5 | `render` | `render_views.mjs` (Node + Chrome) | 12 camera views × shaded/flat/silhouette → `validation/likeness/<name>/` |
| 6 | `likeness` | `validate_likeness.py` | compares renders with the six photographs → `likeness.json`, `contact_sheet.jpg`, `profile_compare.png` |
| 7 | `promote` | — | copies the scored run to `validation/likeness/final/` (the one that ships) |
| 8 | `multicolor` | `build_multicolor.py` | splits body and wheel into closed white/black/red/dark-grey volumes → `multicolor/*.stl`, `*.3mf`, `validation.json` |
| 9 | `validate` | `validate_parts.py` | watertight / orientation / single-solid / Z=0 checks of the six print STLs → `validation/GEOMETRY_REPORT.md` |
| 10 | `previews` | `make_previews.py` (Node + Chrome) | 18 painted and grey images → `previews/` |
| 11 | `package` | `package_handoff.py` | colour/assembly diagram, `START_HERE.html`, `PACKAGE_SHA256SUMS.txt`, `Mustang_Gift_Package.zip` |

A rebuild on another computer reproduces the body to within about 0.04 mm (the decimation step is not bit-exact, so the STL bytes and triangle count differ slightly; the wheels and detail coupon are byte-identical). All geometry checks pass either way.

Design changes go in [scripts/geometry.py](scripts/geometry.py) (every feature solid and the photo-fitted roof/deck profile) and [scripts/regions.py](scripts/regions.py) (the colour regions, used identically by the preview OBJ, the renders and the multicolour STLs). After editing either, run `python run.py build --skip-body` and check the new score in `validation/likeness/final/likeness.json` (currently **88.4 %**, 22/22 features, roof/deck profile within 0.58 mm — see [validation/likeness/README.md](validation/likeness/README.md)).

## 5. Take these to the college

Simplest: hand over **`Mustang_Gift_Package.zip`** — it contains everything below and nothing else. Otherwise take:

- `multicolor/` — separate colour volumes for a compatible multicolour printer (white, black, red, dark grey). Keep each assembly's parts in their shared positions and assign the filaments in the actual slicer. Read the folder's README and `validation.json`.
- `print/` — one body STL, four labelled wheel STLs and a small detail sample. These are the single-material option; the grille, headlamps, lower intake, hood vents, bumper corner slots and rear diffuser are recessed into the surface, so the details read even before painting.
- `previews/` — painted and grey (unpainted) views from every side plus wheel and grille close-ups. Bring your original six photos too.
- `docs/` — the guide, plan check and attribution.
- `validation/` — mesh checks of the six print STLs, the assembled OBJ record, and the photo-likeness report (`likeness/final/contact_sheet.jpg`).

STLs contain geometry only. A coloured preview or OBJ does not make a printer reproduce those colours automatically. The college printer's model and multicolour capability are still unknown. The technician must select its actual profile, check the layer preview and print samples before the full body. **No physical print or machine-ready college G-code is claimed.**

### What to tell the technician

> "This is a 160 mm display model with four separately printed wheels and four colours: white, black, dark grey and red. Please import each set of colour volumes as parts of one assembly, preserve their relative positions, assign the filaments, check scale and supports, and run samples first."

### Printing checklist (short version — full version in [docs/PRINT_AND_PAINT_GUIDE.md](docs/PRINT_AND_PAINT_GUIDE.md))

1. **Ask whether the printer does four colours.** Yes → use `multicolor/`. No → use `print/` (white body, black wheels) and paint the rest.
2. **Import in millimetres at 100 % scale.** Body must read **160.00 × 69.73 × 40.59 mm**, one wheel **23.30 × 23.30 × 8.95 mm**. Never auto-fit, centre or resize individual parts.
3. **Multicolour only:** load each grouped 3MF as *one object with multiple parts*, keep the shared positions (some volumes deliberately float above the bed), and assign filaments by hand — PrusaSlicer does not keep the display colours.
4. **Orientation:** body upright on its flat underside; wheels spoke-face up, flat glue face down. Four wheels.
5. **Print a test first:** one wheel and `print/06_detail_test_1to1.stl`. Check the small features, then print the body.
6. **Starting FDM settings:** PLA, 0.4 mm nozzle, 0.16–0.20 mm layers, 3 walls, 15 % infill, supports under bumpers, mirrors and arches. Single-colour estimate ≈ 8 h 37 min / 104 g (earlier revision, generic simulation). Multicolour time is unknown.
7. **Assemble:** prop the body 6 mm above the table, glue each flat wheel back onto its 11.2 mm pad with the caliper relief facing the rear bumper, let it cure level.

### Which multicolour files go together

| Physical object | Grouped file | Alternative: import these STLs together as parts | Copies and orientation |
|---|---|---|---|
| Body | [body_color_parts.3mf](multicolor/body_color_parts.3mf) | [body_white.stl](multicolor/body_white.stl), [body_black.stl](multicolor/body_black.stl), [body_red.stl](multicolor/body_red.stl) | **One** body, upright on its flat underside |
| Wheel | [wheel_color_parts.3mf](multicolor/wheel_color_parts.3mf) | [wheel_black.stl](multicolor/wheel_black.stl), [wheel_dark_grey.stl](multicolor/wheel_dark_grey.stl), [wheel_red.stl](multicolor/wheel_red.stl), [wheel_white.stl](multicolor/wheel_white.stl) (RTR cap logo) | **Four** complete wheels, spoke face up and flat inner face down |

Use either a grouped 3MF or the corresponding STL set. Import each STL set as **parts of one physical object** and keep shared positions: some colour volumes intentionally do not touch the bed. Never arrange, centre or drop those individual volumes onto the bed. The preview's silver (RTR cap logo, exhaust tips) prints white; its amber markers and the gloss-black pony and 5.0 badges print black.

The colour volumes are produced from the same masks that colour the preview OBJ ([scripts/regions.py](scripts/regions.py)); they are closed, do not overlap (< 0.02 mm³) and rebuild each complete part (< 0.1 mm³), see [multicolor/validation.json](multicolor/validation.json). A PrusaSlicer 2.9.6 import/export audit on the earlier revision of these files kept one grouped object with three named volumes; the container format is unchanged, but **PrusaSlicer did not retain display colours**, so assign filaments manually and confirm them in the colour preview. Other slicers are untested.

### Sizes

Measured body print size: **160.00 × 69.73 × 40.59 mm**. Assembled size: **160.00 × 69.73 × 46.59 mm**. One wheel: **23.30 × 23.30 × 8.95 mm**. Import millimetres at 100 % scale; never auto-fit parts individually. The single-material exports passed the recorded geometry checks on 19 September 2026 ([report](validation/GEOMETRY_REPORT.md)).

## 6. Project layout

```
run.py                  single entry point (setup / check / view / build / step / plate / clean)
requirements.txt        pinned Python packages for .venv
package.json            Node packages for the renderer (three, puppeteer-core)
START_HERE.html         generated landing page with the previews and file links
viewer.html             interactive three.js viewer (serve with `python run.py view`)
Mustang_Gift_Package.zip  generated hand-off archive; PACKAGE_SHA256SUMS.txt lists its contents
scripts/                the pipeline (see section 4); blender_optional/ = old Blender scripts, not needed
print/                  six single-material STLs (body, 4 wheels, detail coupon)
multicolor/             colour volumes as STL sets and grouped 3MFs + README + validation.json
model/                  assembled preview OBJ/MTL
previews/               18 rendered views + 00_COLOR_AND_ASSEMBLY_DIAGRAM.png
docs/                   PRINT_AND_PAINT_GUIDE (.html/.md), PLAN_CHECK.md, ATTRIBUTION.md, SOURCE_LICENSE.txt
validation/             GEOMETRY_REPORT.md, geometry_report.json, likeness/ (photo comparison)
images/                 the six reference photographs of the real car
reference_assets/       the CC BY-NC source body from Thingiverse 3192801 and its licence
work/                   regenerated intermediates (git-ignored)
archive/revision1/      earlier Blender-based revision, reference only
```

This is a simplified miniature derived from an existing Mustang model and customised using the photographs; it is not an exact 3D scan of the car.
